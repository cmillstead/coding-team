# C30

| ID | Pattern | Check before dispatch |
|----|---------|----------------------|
| C30 | `@tags: correction-provenance; reasoning-shape; scope:both` **A change whose whole PURPOSE is to correct wrong facts introduces NEW wrong facts — because the author quotes each MEASUREMENT correctly while narrating its MEANING wrongly, and restates INHERITED figures without re-deriving them, so the correction launders old errors into freshly-dated ones that now read as newly verified.** Stamping "measured `<date>`" beside a claim does not make the claim measured; it makes the next reader trust it more. The failure is invisible to the author because the numbers on the page ARE the numbers that came back — only the sentence built around them diverges from what the run showed. Caught on harness-map TRK-041 (2026-08-04), a documentation-correctness change to an always-loaded instruction file: the author ran the suite against a deliberately misnamed test fixture, recorded the output exactly (`2 failed / 952 passed / 1 skipped`), and then wrote into the file that a misnamed fixture leaves the two smoke tests **SKIPPED** — the opposite of what that very run showed. The skip was gated on `REAL_SAMPLE.is_file()` alone, so an existing-but-misnamed file RUNS both tests and FAILS them. Two more of the same shape in the same diff, from the inheritance half: `99 pre-S6a` and `520 at S1` were figures copied forward from the old text and both were wrong (`git show 44e1df4^:SKILL.md` is **101**; **520** is the ENTERING baseline while the surrounding series quoted COMPLETION figures). Across two cross-model rounds, **5 of 7 findings were defects written BY the correction pass rather than inherited by it** — the pass had a higher defect density than the text it was fixing. | For every factual claim in a correction / doc-fix / figure-update diff, separate three layers EXPLICITLY and check the third against the first: **(1)** the COMMAND you ran, **(2)** its EXACT output, **(3)** the INFERENCE you wrote down. Confirm (3) is what (2) actually shows — not what you expected it to show, and not a tidy generalization of it. A run that produced FAILURES is not evidence about SKIPS; an error message observed under one input is not the error message under a different one. Separately, treat every INHERITED figure the correction restates — a number copied from the old text, a prior handoff, a summary, or an amendment — as **UNVERIFIED until re-derived from a primary source in this session**; a correction pass is exactly where a stale number acquires a fresh date and becomes harder to catch later. Finally, verify by POSITIVE presence, never only by absence of the old string: grepping that the stale text is gone proves REMOVAL, never that the REPLACEMENT is correct. Enumerate every figure the new text asserts and classify each as measured / contract / historical-with-source / unsourced; report the unsourced ones. Pairs with C26 (one-directional teeth — an absence check misses additions) and C29 (vacuous assertion — an assertion satisfied by both the right and the wrong behavior). |

**Design default:** In any correction pass, write the command, its exact output, and your inference as three separate things and confirm the inference matches the output before it lands — then re-derive every inherited figure from a primary source rather than restating it with a new date.
