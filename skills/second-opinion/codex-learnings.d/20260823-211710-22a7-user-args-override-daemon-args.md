# C32

| ID | Pattern | Check before dispatch |
|----|---------|----------------------|
| C32 | `@tags: command-grammar; reasoning-shape; scope:both` **A design/diff that spawns a subprocess with security-critical arguments (bind address, input file, port, endpoint toggles) PLUS a user-/config-supplied passthrough arg list (`extra_args`, `additional_flags`, env-derived opts) lets the passthrough silently OVERRIDE the security-critical args — because most CLIs resolve duplicate options last-wins and the passthrough is appended AFTER the daemon-owned args, and because nothing rejects protected spellings at the trust boundary.** The author reasons "extra_args is for tuning flags like `-ngl 99`" and never enumerates what else the child's parser accepts: a registry/config entry carrying `["--host", "0.0.0.0"]` or a second `--model /tmp/unverified.bin` defeats localhost-only and integrity gating while the wrapper believes it launched what it verified. Caught on the Vagus SPEC_1 cross-model review (Codex F1, rated critical): supervisor built `--model <verified> --host 127.0.0.1 --port N` then `.args(&extra_args)` — a registered entry could re-point the model file and bind the LAN; the same passthrough could also disable an endpoint the daemon depends on (`--no-slots` vs the idle-reaper's busy check). | For any plan/diff that both (a) sets security-relevant argv entries on a spawned process and (b) appends a user/config-controlled arg list: (1) enumerate the child CLI's spellings for each protected option (long, `=`-joined, short) and REJECT them in the passthrough at registration/validation time — an allowlist of known-safe flags is stronger when the surface is small; (2) append daemon-owned args LAST so last-wins parsing favors them even if a spelling slips through (defense in depth, not the primary control); (3) check whether the passthrough can disable an endpoint/behavior the wrapper RELIES on (health, metrics, busy-state) and protect those flags too; (4) add a test registering a protected flag and asserting rejection. "The args come from the user's own config" is not an exemption when a binding rule (localhost-only, fail-closed integrity) claims the property unconditionally. Pairs with C10/C14 (flag-spelling completeness — enumerate ALL spellings of each protected option) and C13 (an invariant is only as true as its least-guarded path). |

**Design default:** When a wrapper spawns a child with both daemon-owned security args and a user-supplied passthrough list, reject every spelling of each protected flag at the trust boundary, append daemon-owned args last, and protect any flag that disables an endpoint the wrapper itself depends on.
