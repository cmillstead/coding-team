# C31

| ID | Pattern | Check before dispatch |
|----|---------|----------------------|
| C31 | `@tags: vacuous-assertion; reasoning-shape; scope:both` **A hygiene/audit scan keyed on SURFACE FORM (hardcoded literals, exact strings) misses the SAME defect expressed through one level of indirection — so the audit's "clean" verdict covers only the representation it grepped, not the resolved value, and a failing COMPOSED pair ships with a green audit.** Canonical instance: a dark-mode/contrast audit that greps a stylesheet for hex/rgb() literals (and passes an allowlist test) structurally cannot see a WCAG-failing pair built entirely from `var()` references — the rule contains no literal at all, so both the human audit and the pinning test walk past it. Caught on harness-map TRK-021 (2026-08-06): Task 5 audited every color LITERAL (7 sites, 5 fixed, 2 exempt, allowlist test added), five same-model auditors and a QA reviewer passed the branch — then Codex round 1 found `#expand-all[aria-pressed="true"]{background:var(--accent-soft);…color:var(--accent)}`, which in the light palette resolves to #6366f1 on #e5e7fb ≈ 3.65:1, under the 4.5:1 AA floor for its 0.85rem text. The rule was ADDED BY THE SAME BRANCH whose audit task ran the literal scan. The same shape recurs anywhere a scan targets the spelling instead of the semantics: secrets scans that miss env-var indirection, size caps that miss includes, dependency audits that miss re-exports. | For any audit/scan whose target property is a function of RESOLVED values (contrast, size, privilege, reachability), ask what indirection layers the codebase offers for expressing that value (CSS custom properties, aliases, env vars, includes, re-exports) — then either resolve through the indirection before checking (parse the palette, compute the ratio on the composed pair) or explicitly enumerate the indirect sites as a second audit surface. A literal-only scan plus an allowlist test proves only "no new LITERALS"; state that limit rather than letting it read as "no new violations." When the branch under review ADDS composed pairs (a new rule pairing two vars), compute the property for each new pair in BOTH/all palettes as part of the audit, not just for the literals the grep surfaced. |

**Design default:** When auditing a resolved-value property (contrast, size, privilege), enumerate the indirection layers first and check the RESOLVED pairs — a literal-only grep plus allowlist test pins spelling, not semantics, and must be labeled as such.
